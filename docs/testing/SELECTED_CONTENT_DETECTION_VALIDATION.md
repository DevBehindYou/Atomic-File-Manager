## Helper increment

SelectedContentMimeResolver and its new SelectedContentMimeResolverTest are the first independently reviewable source increment. No UI integration is included in this commit. The helper recognizes only the exact eight-byte PNG signature, and only when directory/normalized-MIME/known-extension resolution cannot already decide. Actual backend types FILE/SAF/MEDIASTORE are eligible; network and Shizuku backends remain metadata-only. The controlled FTP-ID fixture's delegated InMemoryBackend has actual type FILE; that is not real FTP evidence.

The primary [W3C PNG third-edition specification, section5.2](https://www.w3.org/TR/png-3/) was checked before coding: hexadecimal89 50 4E 47 0D 0A 1A 0A. Recognition is a likely MIME classification, not chunk/CRC/decoding validity. ZIP is never promoted to DOCX. No new dependency, manifest, permission, backend, SDK, plugin-version or benchmark change occurs.

The helper owns an eight-byte buffer and reads at most eight returned prefix bytes, accumulating short reads and converting zero-bulk reads to bounded single-byte progress. It makes no ninth-byte/EOF lookahead, available/mark/reset/seek call, export or full-file copy. This is a caller payload budget, not underlying disk/network traffic: FILE buffering and SAF/MediaStore preflight streams retain their existing semantics. Unsupported network types remain excluded because FTP prefix-close can fail its required226/250 completion and SFTP uses read-ahead. No universal remote/type-detection claim is made.

Acquisition/provider conversion/read/close stay together in one NonCancellable IO region, with an explicitly captured caller context checked before acquisition, before/after every read and after returning. Successful providers are converted exactly once and enter use before a cancellation check can strand an eagerly acquired resource. No stream/provider crosses the withContext return boundary. Cancellation is rethrown, not classified as failure; access/read/factory/close failures remain typed Failure/unresolved recovery. Actual backend preflight streams are separate: the helper does not claim that a complete backend opens only one stream. Cancellation cannot guarantee prompt interruption of an arbitrary blocking provider; it rejects late recognition after the read returns and closes its owned stream. See the official [withContext cancellation and resource-return documentation](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/with-context.html). The documentation's displayed current library version is not a selected dependency upgrade.
