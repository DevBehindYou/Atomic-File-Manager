# Text editor lifecycle and read failures

The editor now holds its draft and selection, original saved text, format, current returned `FileNode`, save state and pending acknowledgement in an Activity-owned ViewModel session. Recreating the Activity reattaches that session instead of reading over an unsaved buffer. A saved replacement with a new opaque ID is an alias for the same session. The enclosing preview must retain its small editor-open flag and original editor ID; it must follow the actual returned node for later reads.

Drafts stay in memory only. They are not written to disk, placed in a Bundle, or promised to survive process death. Closing, discarding, leaving the route and clearing the Activity's ViewModel remove the session and clear draft/original text references. Disposal during `Activity.isChangingConfigurations` keeps it. An accepted save retains its finite payload until the staged save finishes; disposing the route clears its UI state and suppresses late acknowledgement.

Save admission is synchronous and rejects duplicate clicks. Text mutation and closing are disabled while saving. The complete accepted save runs on injected IO inside `NonCancellable`, retaining the existing temporary-write/sync/verify/swap protocol. No Activity callback is stored in the session. The current composition consumes a revision-checked saved-node acknowledgement only while its lifecycle is STARTED; a stopped or destroyed owner cannot claim it. Unexpected save exceptions leave the draft dirty and explicitly say that completion could not be confirmed.

The lazy editor acquisition and all read/save work run through the controller's injected IO boundary. `TextFileEditor.open` now maps backend selection, open, stream construction, read and close exceptions to typed errors; permission exceptions remain access errors, backend-returned failures retain their type, and cancellation is rethrown. Bounded reads check cancellation on every buffer and before decoding, stop at the edit limit plus one byte, close on every path, and make progress if a stream returns zero bytes.

Added coverage: controller duplicate load/save, draft and selection, format preservation, actual saved replacement identity and later save target, typed failure/retry, late read after close, accepted save after owner cancellation, uncertain save failure and read retry. Robolectric recreates a real `ComponentActivity` on APIs 27/34 and verifies the ViewModel/session and draft remain, then verifies finish clears state. Compose tests block close during save and prevent a stopped owner from consuming the replacement callback before the new owner starts. Read tests cover factory/open/provider/read/close failures, permission mapping, cancellation and closure, exact byte cap, zero-byte progress and physical injected worker dispatch.
