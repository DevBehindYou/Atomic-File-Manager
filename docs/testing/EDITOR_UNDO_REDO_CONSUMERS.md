# Bounded editor undo/redo — consumer baseline proposal

Prepared26 October2026 against accepted feature integration3aa7538. Plugin remainsv0.2. These are new actual-dialog consumers, prepared and unrun; no failure/host/device acceptance is inferred until parent executes them. Source author runs no Gradle/ADB.

Source audit: TextEditorSession.edit overwrites its TextFieldValue and has no explicit undo/redo/session history. TextEditorSessionDialog has Find/Wrap/save controls but no Undo/Redo controls. Existing Activity-owned sessions already retain draft/selection/format through recreation and release on finish; preserve that architecture. Do not duplicate safe encoding/BOM/line-ending/staged-write work in TextEditing.

[Official Android keyboard documentation](https://developer.android.com/develop/ui/compose/touch-input/keyboard-input/commands) confirms BasicTextField already supports Ctrl+Z/Ctrl+Shift+Z and describes preview-key interception. [Official AndroidX CoreTextField source](https://github.com/androidx/androidx/blob/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/text/CoreTextField.kt) keeps its internal manager through remember; [its current UndoManager source](https://github.com/androidx/androidx/blob/androidx-main/compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/text/UndoManager.kt) has a bounded character budget. This is not an absent-keyboard-shortcut or unbounded-framework-memory claim, and current main is not proof of an exact pinned binary implementation. Context7 skill was read, but its tools are unavailable; official primary sources are the fallback. No dependency update is proposed.

The new three-case TextEditorUndoRedoComposeTest is committed before production changes. Two cases require public Undo/Redo controls, Unicode replacement/selection restoration, disabled history while saving, no undo-triggered save, replacement-ID ownership and dirty/saved-baseline behavior. A third case exercises the existing keyboard shortcut as a compatibility control, not an expected failure. All save callbacks are finite memory-only spies; deferred completion releases in finally. No user file, provider, permission or database mutation occurs.

Proposed smallest increment: document/session-owned full snapshots, at most20 combined undo/redo entries and16MiB conservative UTF-16 text payload in those history entries, excluding current/saved text and bounded object/framework overhead. Large snapshots evict oldest history; a snapshot over budget cannot be retained, so no promise of unlimited undo. Do not perform whole-text diff scans or persist plaintext in SavedState/Bundle/files. Preserve selection/caret, clear stale composition on a historical restore, keep selection-only movement out of undo, clear redo on a new text edit, keep history after successful save against the latest baseline and replacement identity, and drop history on close. Touch controls and focused editor keyboard shortcuts must share this history without native double-undo; save admission stays unchanged.

Parent must first retain exact RED/control XML/logs, then validate the final source against these consumers, Unicode/branching/budget/session/retention contracts and existing TextEditing safety cases. APK/static/CI/native provider/IME/physical keyboard/release gates remain separate. No complete editor capability-group credit follows from this proposal.
