# PDF engine and API evaluation

Evidence checked **26 October2026**; source `3aa7538fb1b2774fad63935bc6cb3cd206ef01cc`. Research/decision proposal only: no dependency, app source, permissions, device state or build configuration changed. The existing API27 floor, compileSdk36/AGP9.1.1 and native Kotlin/Compose/Atomic UI remain authoritative. Fixed modernization credit stays **0/42 host, 0/42 accepted; 0/8 whole plugins**.

## Existing bounded reader

Atomic's [PdfDocumentSession](../../../app/src/main/kotlin/com/devbehindyou/atomicfilemanager/data/preview/PdfDocumentSession.kt) copies a selected source to a private seekable file, caps spooling at128MiB, serializes page rendering/close and caps raster allocation (default1600px request,2048px edge/four million pixels). [PdfPreviewHelper](../../../app/src/main/kotlin/com/devbehindyou/atomicfilemanager/data/preview/PdfPreviewHelper.kt) opens the original `PdfRenderer(ParcelFileDescriptor)` and supplies raster pages. [PdfPreviewContent](../../../app/src/main/kotlin/com/devbehindyou/atomicfilemanager/ui/components/preview/PdfPreviewContent.kt) owns page/jump/retry/zoom; its outer key and opening effect currently use identity only. Same-ID revision/helper ownership needs a frozen consumer before a bug/fix claim. Generic loader exception mapping also cannot distinguish a required/wrong password from every other opening failure. No text/password/annotation engine is currently wired.

## Platform capabilities by device/API

These are available APIs, **not Atomic implementation or tested file support**. Text APIs need actual text; a scanned page may have no searchable text without separate OCR.

| Device class | Raster fallback | Search / selection / links / password path | Atomic implication |
| --- | --- | --- | --- |
| API27–30 | Existing API21+ renderer remains usable | No verified platform advanced path in this proposal | Preserve bounded raster plus Open with. Do not raise minSdk. |
| API31–34, S-extension<13 | Existing renderer | No `PdfRendererPreV` advanced capability gate satisfied | Same fallback; OS version alone is insufficient. |
| API31–34, S-extension>=13 | Existing renderer | Separate `PdfRendererPreV` and its Page expose advanced text/search/selection/links; `LoadParams` permits password opening | Separate guarded adapter could reuse spool/session ownership. Never call API35 `PdfRenderer.Page` methods merely because the device has an extension. |
| API35–36 | Existing renderer | `PdfRenderer.Page` adds text content, search bounds, selection and links; `PdfRenderer(descriptor,LoadParams)` can open a password-protected document | An API35 adapter can add read-only text/search/password without a bundled parser. Annotation/editing APIs have additional version/extension requirements. |
| Connected phone last recorded API34 | Existing native raster evidence is historical and source-scoped | Its S-extension version was not read by this evaluation | No advanced feature/device pass inferred. Parent can inspect the extension read-only before scheduling its supported adapter tests. |

Primary references: [PdfRenderer constructor/ownership](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer), [API35 Page methods](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page), [PreV class and S-extension13](https://developer.android.com/reference/android/graphics/pdf/PdfRendererPreV), [PreV Page methods](https://developer.android.com/reference/android/graphics/pdf/PdfRendererPreV.Page), [LoadParams](https://developer.android.com/reference/android/graphics/pdf/LoadParams). Renderers own seekable descriptors; parsing/search can be long-running. The platform recommends a minimally privileged isolated process for untrusted inputs. Existing byte/pixel caps are valuable but do not establish a hard CPU timeout or isolation boundary.

Keep runtime capability checks outside API-specific classes. API35-only and PreV-extension adapters need correct SDK/extension annotations and lint/API27 class-loading tests; an unconditional constructor reference in a common API27 initialization path is not acceptable. Retain serialized page/session ownership and cancellable latest query publication; a coroutine cannot promise to interrupt arbitrary synchronous native work halfway through a call. Page search results must be bounded/incremental across the document, with next/previous and coordinate mapping tested against zoom/rotation. Passwords stay in the opening session, with retry/dismiss and no preferences, logs or saved-state persistence.

## Current AndroidX PDF: useful, but not an API27 shortcut

The canonical [release page](https://developer.android.com/jetpack/androidx/releases/pdf) lists **1.0.0-beta01, released26August2026**, with no stable release. Since alpha18, basic reading/rendering supports API28 and extensions below13. This does **not** prove that every advanced feature is backported. The older [implementation guide](https://developer.android.com/develop/ui/views/layout/pdf/implement-pdf-viewer) still describes API31/S-extension13; use the newer feature-specific release/API contracts rather than repeating its blanket minimum for current basic rendering. The current Compose PDF artifact requires compileSdk37/AGP9.2 according to release notes; Atomic pins36/9.1.1. No toolchain upgrade is selected here.

[PdfViewerFragment](https://developer.android.com/reference/androidx/pdf/viewer/fragment/PdfViewerFragment) provides progressive visible-page rendering/search UI, but requires an AppCompat-derived host theme. Atomic's activity is already `FragmentActivity`; its actual `Theme.Atomic` extends a platform theme. Adding the fragment therefore requires an explicit scoped theme/lifecycle/design integration, not changing every app screen's theme by accident. The beta release also labels Compose/editing/OCR surfaces experimental; optional OCR/annotation dependencies and privacy are separate decisions. Preserve API27 raster even if a newer optional view/model is later adopted.

Text-only official POM reads confirmed Apache2 license declarations and these dependency boundaries: [pdf-viewer-fragment beta01 POM](https://dl.google.com/dl/android/maven2/androidx/pdf/pdf-viewer-fragment/1.0.0-beta01/pdf-viewer-fragment-1.0.0-beta01.pom) includes FragmentKTX1.8.1/Core1.13.1/Material1.11/Window1.3 and exact-version document service; [document-service POM](https://dl.google.com/dl/android/maven2/androidx/pdf/pdf-document-service/1.0.0-beta01/pdf-document-service-1.0.0-beta01.pom) itself depends on pdf-viewer; [pdf-core POM](https://dl.google.com/dl/android/maven2/androidx/pdf/pdf-core/1.0.0-beta01/pdf-core-1.0.0-beta01.pom) is a lighter model artifact. A model-only choice still needs an actual loader/renderer; it is not an independent API27 parser. The complete resolved graph, AAR minimum/compile metadata and notices remain unverified by a build.

Smallest useful source PR: add genuine unchanged-source consumers for same-ID revision/helper replacement, failed open/Retry and blocked source-switch/Close; correct only ownership/failure context while preserving spool/pixel caps and latest-page publication. This can proceed without choosing a new engine or waiting for benchmark permission changes. Subsequent platform adapter PR must define capability-aware controls and password handling, use text-bearing/password/scanned/malformed fixtures, preserve originals, and test API27 class loading plus both supported and unsupported device gates. Keep continuous pages/thumbnails/bookmarks/printing/export, advanced annotation and structural edit/OCR requests separately tracked under PDF1–PDF5; none is silently dropped or credited by this research.

Acceptance before any engine adoption: exact resolved source/artifacts/notices/ABI metadata; focused/current-head host/static/build/Lint; realAPI27/API34-with-extension/API35+ fixtures where applicable;1000+ pages, high-resolution mixed sizes and malformed inputs; temporary-source/descriptor/page/worker cleanup, cancellation/stale searches, rotation, provider loss, privacy/original integrity and measured release-like memory/first-page/search/paging/size costs. Current research supplies no new test, performance or release pass.
