## Release acceptance

- Every advertised function in each of the eight bundled plugins has actual consumer and relevant native-format evidence. No dead controls, static GIF labelled as animation, silent truncation, false success or unsupported capability claims.
- Resolve known release-blocking defects; preserve failures, root causes, fixes and regression evidence in each plugin's maintained features/tasks/bugs/validation record.
- Complete opening, playback/rendering, user controls, source replacement, cancellation/close, lifecycle/recreation, error/recovery and original-integrity journeys where applicable. Distinguish actual platform/provider/format tests from mocks, source inspection and UI-only surface checks.
- Exercise applicable local/SAF/MediaStore/SD/USB/network sources, corrupted/large inputs, revoked access and interrupted operations using authorized owned fixtures. A single FILE test is not the whole provider matrix.
- Theme, narrow/rotated/large-font/accessibility behavior and useful limitations/fallbacks are required for the shipped functionality.
- Current-source host/static/Lint, debug/test/release packaging, R8 runtime, review, accepted dependencies and a clean integration trial must pass. Promote to main/release only through the separately validated release process.
- Collect required performance/resource evidence; retain the owner's benchmark deferral and unchanged phone permissions. The stable target does not waive an open benchmark gate or authorize root probes.
