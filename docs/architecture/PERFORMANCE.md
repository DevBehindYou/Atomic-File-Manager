# Performance Strategy

> **Evidence, 17 October 2026:** this is a target strategy. Current measured/unmeasured results are recorded in [PERFORMANCE_BASELINE](../testing/PERFORMANCE_BASELINE.md). CI assembles benchmarks but does not run the described per-merge device regression gate. No startup, frame-time, memory or throughput improvement is claimed without a measurement.

Budgets are in `../NON_FUNCTIONAL_REQUIREMENTS.md` §1. This document is *how they are met and
measured*.

## 1. Startup

| Technique | Detail |
|---|---|
| Baseline profile | Generated by the `:benchmark` module for cold start + browse scroll. Typically 20–30% start-up improvement; non-negotiable |
| Splash screen API | `androidx.core.splashscreen`, no custom splash Activity |
| Lazy DI | Hilt entry points only; nothing heavy in `Application.onCreate` |
| No I/O on the main thread at start | Volumes, favourites and recents all load asynchronously; Home renders skeletons in the first frame |
| Room built lazily | `RoomDatabase` created on first use, off the main thread |
| Glass tier resolved async | Home renders Tier C for the first frame and upgrades — never blocks the first frame on a capability probe |

Measured with `macrobenchmark` `StartupMode.COLD`, 10 iterations, on the reference device,
run in CI on every merge to `main`.

## 2. Directory listing

* Backends stream in chunks of 200; the UI renders `Partial` immediately.
* Sorting happens on `Dispatchers.Default` on the full list once it is complete, and on each
  partial chunk only if the list is still short (< 2,000).
* Metadata that is not needed for the row (folder sizes, `childCount`, `extras`) is loaded
  lazily, per visible item, and cached.
* Thumbnails load only for visible items, with Coil's default prefetch window.
* 10,000-item directories are a test case, not an edge case.

## 3. Scrolling

| Rule | Why |
|---|---|
| Stable keys + `contentType` | Node reuse |
| `@Immutable` UI models | Skips recomposition |
| No allocation in the item lambda | GC pressure during fling causes dropped frames |
| Thumbnails decoded at target size (`inSampleSize`) | Full-resolution decode of a 12 MP photo for a 44dp icon is the single biggest jank source in file managers |
| No glass inside lists | Backdrop capture per item is fatal |
| Fixed row height where possible | Avoids remeasure |

Verified by a macrobenchmark scroll test asserting frame duration p90 and p99.

## 4. Thumbnails

```text
1. MediaStore thumbnail (already generated by the system)   — cheapest
2. ContentResolver.loadThumbnail() (API 29+)                — cheap, correct orientation
3. Coil decode with inSampleSize to 2× display size         — moderate
4. FileTypeIcon                                             — free
```
Memory cache = `maxMemory / 8`. Disk cache = 250 MB LRU. Video frames come from
`MediaMetadataRetriever` on `Dispatchers.IO` with a hard timeout of 2 s per file, after which
we fall back to the type icon — a corrupt video must not stall the list.

## 5. Search

Covered in `SEARCH_ARCHITECTURE.md` §7. Key performance decisions: concurrent sources,
10 Hz emission throttle, 250 ms debounce, `flatMapLatest` cancellation, 5,000-result cap.

## 6. Storage scan

* Single walk that computes category totals, top-N files and top-N folders simultaneously.
  Three separate walks would be three times the I/O.
* Top-N maintained with a bounded min-heap, not by sorting everything at the end.
* Progress reported per top-level directory so the bar moves meaningfully.
* Results cached in Room with `scannedAt`; the UI shows cached data instantly and offers
  a rescan.
* Runs at `THREAD_PRIORITY_BACKGROUND`.

## 7. File operations

* Buffer sizing: 64 KB (< 8 MB files) / 256 KB (larger).
* Progress emission throttled to 4 Hz.
* Same-volume moves use `rename()` — O(1) instead of O(size).
* Batches sorted so small files go first, giving the user visible early progress.
* Never more than 2 concurrent operations, and never 2 on the same volume.

## 8. Glass

| Rule | Budget |
|---|---|
| Total glass cost | < 4 ms/frame on the reference device |
| Backdrop re-capture | Only when the backdrop actually changed, never per frame |
| Glass area | ≤ 25% of viewport |
| Shader compilation | Once, cached; measured at first use and logged |
| Ambient animation | Max 1 running app-wide |

`JankStats` feeds `GlassCapabilityManager`; three consecutive bad windows demote the tier.

## 9. Memory

* Peak heap target < 180 MB.
* `onTrimMemory` clears the thumbnail memory cache and demotes the glass tier.
* No `Bitmap` held outside Coil's caches.
* Cursors always in `use { }`.
* Directory lists capped at 50,000 in memory.
* LeakCanary in debug; a leak in a release candidate blocks the release.

## 10. Measurement

| Tool | What |
|---|---|
| `macrobenchmark` | Cold/warm start, scroll frame timing, folder-open latency |
| `microbenchmark` | Sort, hash, path parsing |
| `JankStats` | Runtime frame timing, feeds the tier watcher |
| Perfetto / systrace | Manual investigation of specific regressions |
| Compose recomposition counts | Asserted in tests for the hot components |
| Android Studio Power Profiler | Battery cost of Tier A over a 10-minute session |

CI runs the macrobenchmarks on every merge and **fails the build on a > 10% regression**
against the stored baseline.
