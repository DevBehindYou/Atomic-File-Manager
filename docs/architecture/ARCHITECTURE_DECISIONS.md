# Architecture decisions — modernization

17 October 2026. Existing decisions remain in [handover DECISIONS](../ai-handover/DECISIONS.md); this ledger records this audit's additions without duplicating that history.

* **ADR-M01: preserve the modular monolith and manual DI.** Existing storage seams and tests justify incremental changes. No measured build reason for new Gradle modules and no benefit proven for Hilt migration.
* **ADR-M02: durable admission precedes mutation.** An asynchronous enqueue API does not justify running before Room acknowledges intent. A failed initial journal write fails closed. Keep optional journal-less testing mode explicit.
* **ADR-M03: stage output and never silently overwrite.** Archive/share code must preserve preexisting data on failure. Treat no-clobber publication and crash durability as separate guarantees. Generic StorageBackend does not yet promise atomic external-writer exclusion.
* **ADR-M04: lifecycle owns readers; application owns mutations.** Secondary browsing ViewModels must be cleared with their owner and are unnecessary in single-pane mode. Queued operations survive screen removal.
* **ADR-M05: bound work before increasing concurrency.** Keep serial mutations; remove unbounded progress-write amplification and share connection backlog. Real progress throttling is justified by source-level event count, not invented device speedups.
* **ADR-M06: source and current evidence supersede historical status.** Retain historical product plans, add authoritative current inventory and explicit evidence scope. No claim of production readiness until device/recovery/signing gates pass.
* **ADR-M07: provider identity is opaque.** SAF ancestry compares authority/document identity across grants and uses provider confirmation or a cancellation-aware descendant walk. Breadcrumbs use actual resolved parents and visited history. Unavailable ancestry fails closed before mutation; unknown breadcrumb parents show only known locations. SFTP/SMB storage roots have no parent.
* **ADR-M08: protocols must enforce the safety boundary.** FTPS verifies TLS on both channels. DAV writes use create-only PUT and non-overwriting MOVE. XML and FTP metadata are bounded and failed/incomplete replies become failures. DAV discard deletes only a successfully created resource identified by a strong ETag; missing validators preserve staging instead of risking another writer's data.
* **ADR-M09: cancellation safety is not crash atomicity.** Trash move/record reconciliation and restore identity changes run in a small non-cancellable metadata section after a cancellation checkpoint. This reduces in-process orphaning without claiming a transaction across storage and Room. A future restart repair must compare persisted identities with actual holders, report unrecorded or stale entries, and preserve the only copy; it must never purge an unknown holder as routine cleanup. Real process-kill tests and a persisted multi-phase repair protocol remain release work.
* **ADR-M10: preference IO includes construction and must preserve accepted UI intent.** Folder sorting, bubble position, Storage server/sync snapshots and Home directory resolution move their complete storage access to injected IO boundaries. Readers remain cancellable; finite accepted preference writes finish after disposal without publishing callbacks to a closed screen. Shared ordering and repository writer locks prevent screen replacement and multiple store instances from losing newer metadata. Gesture/sort revisions reject stale initial snapshots. Existing preference formats and `apply()` durability semantics remain unchanged. See [implementation and validation](../testing/PREFERENCE_IO_VALIDATION.md); the later comparison-route change has its [own validation scope](../testing/FOLDER_COMPARE_PREFERENCE_IO_VALIDATION.md).

* **ADR-M11: load saved settings before composing normal app content.** The activity waits on injected IO for the existing process-shared, fully seeded repository, then retains the splash until themed content commits. Failed initialization shows explicit retry/close controls instead of editable defaults. Lifecycle cancellation rejects late results, and pending external requests survive recreation with acknowledgement tied to the handled target. See [startup validation](../testing/SETTINGS_STARTUP_VALIDATION.md).

* **ADR-M12: decorative video frames must not instantiate the native retriever in the app.** API34 testing exposed a retriever finalizer watchdog crash. A distinct Coil model/fetcher requests provider thumbnails with two concurrent IO requests, cancellation and bounded bitmap ownership. Missing provider support retains the type icon; it does not fall back to the whole video. API27/28 queries cached thumbnail images directly because the legacy convenience helper can fall back to native frame extraction. Playback and explicit metadata remain separate acceptance surfaces. See [thumbnail validation](../testing/FILE_THUMBNAILS_VALIDATION.md).

* **ADR-M13: browsing presentation must preserve the active pane's identity and work.** Storage shortcuts navigate the existing pane model instead of rekeying it, so Copy/Move clipboards and visited history survive. The UI matches enumerated roots without probing filesystem paths or decoding provider IDs. List/Grid shares item interactions and thumbnail ownership; its preference is persisted, while type filters stay pane-local. Popups observe application/request-owned tasks and never create decorative work. Access requests refresh storage choices without retaining denied requests for later navigation replay. See [Files validation](../testing/FILES_WORKSPACE_VALIDATION.md).

* **ADR-M14: adaptive menus and file decoration stay in presentation.** Top options measures actual content within the host window. Bottom action menus share responsive icon cards and preserve action ownership, disabled state and destructive confirmations; forms and explanatory choices retain their own layouts. File-family symbols and light/dark colours use existing metadata without reading file contents, altering routing or replacing decoded previews. Meaningful outlined symbols accompany colour. Native-font geometry tests and colour contrast checks validate the presentation. See [menu/icon validation](../testing/MENU_REFINEMENT_VALIDATION.md).

API guidance consulted: [Kotlin cancellation](https://kotlinlang.org/docs/cancellation-and-timeouts.html), [ViewModel lifetime](https://developer.android.com/topic/libraries/architecture/viewmodel), [Gradle wrapper integrity](https://docs.gradle.org/current/userguide/gradle_wrapper.html). The Context7 skill was inspected, but this session exposes no Context7 tools; official documentation is the fallback. Existing pinned versions remain unchanged.
